# TOPBAR_FEATURES_SPEC.md

마지막 업데이트: 2026-05-02  
문서 성격: **상단 글로벌 메뉴(Topbar) 초상세 기획 및 기능 명세서 — 완전판 갱신본**

본 문서는 Sherpain21 플랫폼의 **최상단 네비게이션(Topbar)** 에 위치한 글로벌 메뉴의 기획 의도(Why), 세부 기능 요구사항(What), 그리고 구현 방법(How)을 상세하게 정리한 문서입니다.

이 문서는 단순히 메뉴 이름만 기록하는 요약본이 아니며,
향후 코드를 전면 초기화하고 다시 개발하더라도 이 문서를 기준으로 **동일한 UX 철학과 구조를 복원할 수 있어야 합니다.**

또한 현재 워크스페이스 기준으로 실제 반영된 파일 구조와 구현 상태도 함께 반영하여,
기획 문서와 실제 코드 간의 차이를 줄이는 것을 목표로 합니다.

---

## 0. 이 문서의 사용 원칙

- 본 문서는 **탑바 전용 바이블** 입니다.
- 새 채팅, 새 세션, 새 작업자는 반드시 `SHERPAIN21_MASTER_PROMPT.md` 와 이 문서를 먼저 읽고 탑바를 수정해야 합니다.
- 메뉴를 줄이거나 하위 항목을 임의로 없애서는 안 됩니다.
- 탑바는 페이지마다 다르게 보이는 컴포넌트가 아니라, **내부 앱 전체에 공통 적용되는 글로벌 네비게이션** 이어야 합니다.
- 탑바는 텍스트 중심으로 신뢰감 있는 B2B 느낌을 유지해야 하며, 과한 장식성은 지양합니다.
- 기능성 아이콘(알림, 사용자 메뉴, 사이드바 토글, DevTools)은 허용되나, **글로벌 메뉴 자체는 텍스트 중심**으로 유지합니다.
- 탑바 하단 라인은 사이드바의 상단 경계선과 시각적으로 이어져야 합니다.
- 경로 규칙은 반드시 `/app/...` 기준을 유지합니다. `/frontend/app/...` 식 경로는 금지합니다.

## 1. Topbar 공통 UI/UX 규칙 (All Pages)

### 1.1 기획 의도 (Why)

#### 1) 일관성 확보
기존 버전에서 페이지마다 메뉴 개수가 다르거나, 어떤 페이지는 상단이 비어 있고 어떤 페이지는 메뉴가 과하게 붙어 있는 식의 문제는 사용자가 플랫폼 안에서 길을 잃게 만듭니다.  
탑바는 **어느 페이지에 있든 동일하게 보이는 글로벌 이동 수단** 이어야 하며, 사용자가 커뮤니티에서 고객센터로, 고객센터에서 미션 마켓으로, 미션 마켓에서 제휴 페이지로 빠르게 이동할 수 있어야 합니다.

#### 2) B2B의 신뢰감
Sherpain21은 감성형 소비재 앱이 아니라, 실무형 운영 도구 플랫폼에 가깝습니다.  
따라서 탑바는 글래스모피즘이나 과한 장식, 지나친 반투명 효과보다는 **단정한 화이트 배경 + 텍스트 중심 + 안정적인 경계선** 을 유지해야 합니다.

#### 3) 전체 서비스 허브 역할
상단 메뉴는 단순한 헤더가 아니라 다음의 허브입니다.
- 커뮤니티 체류 시간 증가
- 자유홍보/제휴 유입 강화
- 에스크로 의뢰 전환 유도
- 문의/고객센터 진입 단순화
- 알림/유저 메뉴/개발용 툴 접근

즉 탑바는 **플랫폼의 핵심 서비스들을 가로로 연결하는 글로벌 허브**입니다.

### 1.4 현재 구현 아키텍처 (How)

#### `topbar-core.js`
탑바의 실제 구현체입니다.
- 메뉴 데이터 정의
- 현재 URL 기준 active 판별
- 드롭다운 렌더링
- 알림 패널 렌더링
- 사용자 패널 렌더링
- Developer Tools 패널 렌더링
- open/close 이벤트 처리
- 외부 클릭 닫기
- ESC 닫기

#### `topbar.js`
탑바 엔트리 파일입니다.
- `topbar-core.js`를 로드
- 초기화 실행
- 각 HTML은 이 파일만 공통으로 불러오면 됨

#### `topbar.css`
탑바 전용 스타일입니다.
- 높이, padding, 드롭다운, 패널, 밑줄, hover 상태 등 정의

---

### 1.5 스타일 규칙 (Current Standard)

#### 높이
- 현재 구현 기준: **64px**

#### 배경
- `background: #fff`
- 반투명/블러 최소화
- 실제 구현은 solid white 기준

#### 경계선
- `border-bottom: 1px solid var(--color-gray-200)`
- 사이드바 상단 Sherpain 헤더 경계선과 같은 톤으로 유지

#### 타이포
- `font-family: var(--font-korean)`
- 메뉴 텍스트는 가독성이 높은 Pretendard 계열 기준

#### 메뉴 스타일
- 메뉴는 텍스트 중심
- 기본 상태: 회색 계열 텍스트
- hover / active 상태: 진한 텍스트 + 하단 2px accent line

#### 아이콘 정책
- 메뉴명 왼쪽 장식 아이콘: 사용하지 않음
- 기능 버튼(사이드바 토글 / 알림 / 유저 / Dev): 허용

---

### 1.6 드롭다운 규칙 (Current Standard)

#### 등장 방식
- 데스크톱: hover + focus
- 터치/좁은 환경: click 토글

#### 닫힘 방식
- 바깥 영역 클릭 시 닫기
- ESC 키 입력 시 닫기

#### 스타일
- 순백색 배경
- 연회색 border
- 부드러운 shadow
- 항목마다 hover 배경
- 밑줄 없음

#### 컬럼 수
- 커뮤니티: 2열
- 나머지 메뉴: 1열

---

### 1.7 Active 판별 규칙

탑바의 active 상태는 다음 3가지를 함께 봅니다.

1. `pathname`
2. `?tab=`
3. `#hash`

예를 들어:
- `/app/community/board.html?tab=attendance`
  - 상위 메뉴: 커뮤니티 active
  - 하위 항목: 출석체크 active

- `/app/partner/services.html#promo`
  - 상위 메뉴: 제휴사 및 자유홍보 active
  - 하위 항목: 자유홍보 게시판 active

## 2. 메뉴 1: 커뮤니티 (Community) — `board.html`

### 2.1 기획 의도 (Why)

#### 1) 체류 시간 증가 및 바이럴
사용자(자영업자, 마케터)가 단순히 툴만 쓰고 떠나는 것이 아니라,
매일 들어와서 정보를 얻고 질문하며 소통하는 자생적 생태계를 만드는 것이 목적입니다.

#### 2) 수익화 공간 확보
커뮤니티 상단 영역은 향후 가장 트래픽이 많이 몰릴 곳입니다.  
따라서 이 위치는 스폰서십/배너 광고/프로모션 안내에 적합합니다.

#### 3) 출석체크 리워드
매일 출석체크 시 소량의 눈덩이를 지급해 DAU(일일 활성 사용자 수)를 높이고,
커뮤니티의 반복 방문 루틴을 형성하는 것이 목적입니다.

---

### 2.2 드롭다운 하위 메뉴
- 공지사항 (`?tab=notice`)
- 가입인사 (`?tab=greeting`)
- 출석체크 (`?tab=attendance`)
- 자유게시판 (`?tab=free`)
- 정보공유 (`?tab=share`)
- 로직분석 연구실 (`?tab=logic`)

---

### 2.3 페이지 구조 (Current Frontend Standard)

현재 커뮤니티 페이지는 다음 구조를 따릅니다.

```text
상단 배너 예시
탭 메뉴
제목 / 설명 / 글쓰기 버튼
게시글 + 검색행
테이블
페이지네이션
상세 모달
글쓰기 모달
```

#### 검색 규칙
- 공지사항: 검색 없음
- 가입인사: 검색 없음
- 출석체크: 검색 없음
- 자유게시판 / 정보공유 / 로직분석 연구실: 검색 있음

#### 페이지네이션
- 30개 단위
- 하단 숫자 버튼

#### 상세
- 제목 클릭 → 상세 모달
- 댓글/대댓글 표시 및 작성

#### 출석체크
- 한 줄 인사말 작성
- 출석 기록 피드 표시
- 연속 출석일/오늘 출석 여부 표시

---

## 3. 메뉴 2: 제휴사 및 자유홍보 — `services.html`

### 3.1 기획 의도 (Why)

#### 1) 공식 제휴사 우대
일반 유저의 홍보글과 공식 제휴사를 같은 레벨에서 보여주면,
제휴사가 비용을 지불할 이유가 없어집니다.  
따라서 공식 파트너는 별도 탭/섹션에서 더 신뢰감 있게 노출되어야 합니다.

#### 2) 자유홍보 수익화
누구나 자기 사업을 홍보하고 싶어하는 니즈를 활용하되,
무분별한 도배를 막고 눈덩이 사용처를 만드는 구조가 필요합니다.

---

### 3.2 드롭다운 하위 메뉴
- 공식 제휴 파트너사 (`#premium`)
- 자유홍보 게시판 (`#promo`)

---

### 3.3 페이지 구조 (Current Frontend Standard)

현재 제휴/홍보 페이지는 다음 구조로 통일되었습니다.

```text
탭
제목 / 설명 / 액션 버튼
목록 제목 + 검색행(자유홍보에서만)
테이블
페이지네이션
글쓰기 모달
```

#### 탭
- 공식 제휴 파트너사
- 자유홍보 게시판

#### 검색 규칙
- 공식 제휴 파트너사: 검색 없음
- 자유홍보 게시판: 검색 있음

#### 자유홍보 정책 예시
- 1일 1회 무료
- 이후 500 눈덩이 차감

---

## 4. 메뉴 3: 모집 및 의뢰 (에스크로) — `missions.html`

### 4.1 기획 의도 (Why)

#### 1) 핵심 캐시카우 및 양면 시장
자영업자(의뢰자)와 일반 사용자(수행자)를 연결하는 플랫폼의 핵심 기능입니다.

#### 2) 신뢰 확보 (에스크로)
말로만 보상 약속하는 구조가 아니라,
미리 눈덩이를 예치시키는 구조를 통해 먹튀를 막는 것이 목적입니다.

#### 3) 수익화
- 미션 보상금 기준 10% 수수료
- 잔고/출금 정책과 연계한 눈덩이 운영

---

### 4.2 드롭다운 하위 메뉴
- 모집 (의뢰하기) (`?tab=recruit`)
- 의뢰 (수행하기) (`?tab=apply`)

---

### 4.3 페이지 구조 (Current Frontend Standard)

```text
탭
제목 / 설명 / 액션 버튼
목록 제목 + 검색행
테이블
페이지네이션
미션 등록 모달
예치 계산기
```

#### 검색
- 모집/의뢰 둘 다 검색 가능

#### 등록 모달
- 유형
- 제목
- 상세 가이드
- 보상 눈덩이
- 수수료 10%
- 총 예치 필요 눈덩이 계산

---

## 8. 경로 및 라우팅 규칙

### 8.1 경로 기준
탑바는 반드시 `/app/...` 기준으로 이동한다.

#### 올바른 예
- `/app/community/board.html?tab=notice`
- `/app/support/cs.html?tab=faq`
- `/app/escrow/missions.html?tab=recruit`

#### 금지 예
- `/frontend/app/community/board.html?...`

### 8.2 active 판별 규칙
- `pathname`
- `?tab=`
- `#hash`
를 함께 사용한다.

### 8.3 로더 구조
현재 HTML들은 보통 아래를 사용한다.
```html
<script defer src="../../src/js/topbar.js"></script>
```

`topbar.js`는 내부적으로 `topbar-core.js`를 로드/초기화한다.

## 9. 현재 구현상 유지보수 원칙

### 9.1 탑바 수정 위치
탑바 기능 수정은 원칙적으로:
- `topbar-core.js`
- `topbar.css`
에서만 수행한다.

### 9.2 HTML 개별 수정 최소화
페이지별 HTML은 공통 로더만 두고,
탑바 구조를 각 HTML마다 따로 박아넣지 않는다.

### 9.3 사이드바 경계선 정렬 유지
탑바 하단 라인은 사이드바 상단 Sherpain 영역의 경계선과 시각적으로 맞아야 한다.

### 9.4 플레이스 순위 조회 예외 확인
플레이스 순위 조회는 특수 페이지이므로 탑바가 깨지지 않는지 항상 확인해야 한다.
현재는 `topbar.css`의 flex 보강으로 안정화 방향을 적용했다.
