# Sherpain21 V1 / V1.5 → 현재 구조 이식 대기열 및 정리 문서 — 완전판 갱신본

마지막 업데이트: 2026-05-02  
문서 성격: 예전 버전(v1 / v1.5) 화면과 기능을 현재 Sherpain21 구조로 옮길 때의 우선순위, 상태, 남은 과제를 기록하는 기준 문서

이 문서는 과거 버전에서 존재하던 화면/기능을 현재 Sherpain21 구조로 이식할 때,
어떤 페이지가 이미 구조 통일을 마쳤고,
어떤 페이지는 아직 예전 코드/스타일을 유지하고 있으며,
어떤 기능은 UI만 정리됐고 실제 API 연결은 남아 있는지를 정리한 **완전판 이식 큐 문서**입니다.

이 문서는 단순 TODO 목록이 아니라,
- 현재 어떤 페이지가 이미 이식되었는지
- 어떤 페이지가 부분 이식 상태인지
- 어떤 CSS/JS 구조를 써야 하는지
- 다음에 무엇부터 옮겨야 하는지
를 새 세션/새 작업자가 빠르게 파악하도록 돕는 기준 문서입니다.

---

## 1. 이 문서의 목적

Sherpain21은 한 번에 처음부터 완전히 새로 만들어진 시스템이 아니라,
기존 v1/v1.5 기반의 기능과 페이지들을 점진적으로 이식하고 정리해온 프로젝트입니다.

따라서 현재 프로젝트를 이해할 때는 다음을 구분해야 합니다.

1. **원래 있던 기능**
2. **새 구조로 UI만 재구성된 기능**
3. **실제 API/DB 연결까지 끝난 기능**
4. **아직 예전 구조를 일부 유지하는 특수 페이지**

이 문서는 그 차이를 기록하기 위해 존재합니다.

## 2. 현재 전체 이식 상태 요약

### 2.1 레이아웃/구조 통일 완료 페이지
아래 페이지는 상단 메뉴 체계와 공통 레이아웃 철학에 맞게 구조 통일을 마쳤습니다.

- 커뮤니티
- 프로그램 문의
- 고객센터
- 제휴사 및 자유홍보
- 모집 및 의뢰

이 페이지들은 현재 다음 구조를 공유합니다.

```text
탭
제목 / 설명
액션 버튼
목록 제목 + 검색행
테이블 또는 리스트
페이지네이션
모달
```

### 2.2 구조 복구 완료 but 추가 정리 필요
- 플레이스 순위 조회

이 페이지는 예전 구조를 되살리는 데는 성공했지만,
아직 다음 이슈가 남아 있습니다.
- CSS 완전 분리 미완
- inline style 비중 존재
- 공통 구조와의 접점 정리 필요
- Worker API와의 지속 동기화 필요

### 2.3 UI 정리 완료 but 실제 API 연결 미완 페이지
아래는 구조와 프론트 UX는 거의 정리되었지만,
실제 서버 API/D1 연동이 아직 완전히 끝나지 않은 영역입니다.

- 프로그램 문의
- 고객센터
- 자유홍보 게시판
- 모집 및 의뢰

### 2.4 실제 API 연결 1순위 진행 중 페이지
- 커뮤니티
  - 목록
  - 검색
  - 페이지네이션
  - 글쓰기
  - 상세
  - 댓글/대댓글
  - 출석체크
  - dev session 기반 테스트

## 5. 이식 우선순위 (현재 최신 기준)

### 1순위 — 커뮤니티 API 완료
가장 먼저 끝내야 하는 이유:
- 게시판형 공통 구조의 기준점
- 댓글/대댓글/페이지네이션/출석체크까지 포함
- 다른 문의/고객센터 게시판 API의 템플릿 역할 가능

포함 항목:
- 공지사항
- 가입인사
- 출석체크
- 자유게시판
- 정보공유
- 로직분석 연구실
- 상세/댓글/대댓글
- dev session 테스트

### 2순위 — 프로그램 문의 / 고객센터 API
이유:
- 이미 `board.css` 구조로 통일됨
- 커뮤니티 API 패턴을 재사용 가능
- FAQ / Q&A / 1:1 구분만 추가하면 됨

### 3순위 — 자유홍보 / 모집 및 의뢰 API
이유:
- `marketplace.css` 구조 통일 완료
- 실제로는 눈덩이 차감/예치/정산 규칙이 있어 백엔드 중요도 높음

### 4순위 — 플레이스 순위 조회 CSS 완전 분리
이유:
- 기능은 살아 있으나 문서/구조/스타일 기준으로 보면 아직 예외 페이지
- 장기 유지보수 위해 반드시 정리 필요

### 5순위 — Worker `index.js` 완전 분리
이유:
- 현재 monolith 구조는 위험
- 기능이 더 붙을수록 분리 필요성 증가
- 다만 커뮤니티/문의 API가 먼저 안정화된 뒤 착수하는 것이 안전

## 7. Worker 분리와의 관계

V1/V1.5 이식은 단순히 화면을 옮기는 문제가 아니라,
현재 monolith Worker와의 결합 상태를 정리하는 과정과도 연결됩니다.

즉, 아래 두 축이 함께 움직입니다.

### 프론트 이식 축
- HTML 구조 통일
- CSS 분리
- 공통 UI 재사용
- 검색/페이지네이션/모달 공통화

### 백엔드 정리 축
- 레거시 게시판 API 유지
- V2 API 신설
- 공통 helper 분리
- index.js split 진행

따라서 이 문서는 프론트 전용 TODO가 아니라,
**화면 이식 + API 연결 + Worker 구조 정리의 중간 지도** 역할을 합니다.

## 8. 남은 위험 요소

### 8.1 문서와 실제 코드 불일치 위험
- 페이지 구조는 정리됐는데 문서가 옛 상태면 다음 세션에서 다시 꼬임
- 따라서 이 문서와 `FILE_MAP.md`, `CURRENT_STATUS.md`를 항상 함께 갱신해야 함

### 8.2 플레이스 순위 조회 예외화
- 이 페이지가 계속 별도 예외로 남으면 유지보수 비용이 커짐
- CSS 분리 작업을 뒤로 미루더라도, 반드시 큐에 유지해야 함

### 8.3 monolith 의존
- 프론트가 정리될수록 오히려 백엔드 monolith가 병목이 됨
- index.js 분리를 너무 뒤로 미루면 다시 속도/안정성 문제가 커질 수 있음

## 9. 다음 세션에서 이 문서를 활용하는 방법
새 작업자/AI는 이 문서를 보고 다음을 판단해야 합니다.

즉, 이 문서는 단순 TODO 메모가 아니라,
**이식 진행률을 체계적으로 기록하는 기준 문서**입니다.

## 10. 최종 선언
Sherpain21의 V1/V1.5 이식은 “겉보기만 맞추는 작업”이 아닙니다.  
반드시:
- UI 구조 통일
- CSS 분리
- 공통 컴포넌트 재사용
- API 연결
- Worker 정리
가 함께 가야 합니다.

이 문서의 우선순위와 상태 기록은,
현재 프로젝트를 **단계적으로, 하지만 축소 없이** 완성시키기 위한 기준으로 유지되어야 합니다.
