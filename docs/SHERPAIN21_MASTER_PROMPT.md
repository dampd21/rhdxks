## 0. 이 문서의 지위
이 문서는 Sherpain21 프로젝트에서 **가장 우선순위가 높은 작업 기준 문서**다.  
새 채팅, 새 세션, 새 작업자, 새 AI가 들어와도 **반드시 이 문서를 먼저 읽고** 그 다음에 다른 파일과 문서를 읽어야 한다.

이 문서를 읽지 않은 상태에서:
- 공용 파일을 수정하거나
- 구조를 재편하거나
- 스타일을 손보거나
- API를 추가/변경하거나
- 문서를 갱신하는 행위는 **금지**한다.

이 문서의 목적은 단순한 코딩 지침이 아니라,
**프로젝트의 기능 보존, 구조 일관성, 문서 충실성, 운영 안정성**을 강제하기 위한 것이다.

## 1. 절대 금지 항목

### 1-1. 기능 축소 금지
다음과 같은 행위는 전부 금지한다.
- “우선 간단히”라는 명목으로 기능 일부 제거
- 기존에 존재하던 메뉴/버튼/탭/패널 삭제
- 화면은 유지하되 실제 동작을 임시 mock으로 치환한 뒤 완료 처리
- 게시판/문의/고객센터/홍보/미션 기능을 TODO로 미뤄둔 채 완료 선언
- 기존 API 응답 필드를 줄이는 행위
- 레거시 경로를 호환 계층 없이 제거하는 행위

### 1-2. 코드 생략/중략 금지
다음과 같은 응답 방식은 금지한다.
- “나머지는 동일”
- “이 부분은 생략”
- “중략”
- “기존 코드 그대로”라고만 쓰고 실제 파일 전체를 제공하지 않는 행위
- 패치 포인트만 주고 실제 최종 파일을 제공하지 않는 행위

**프로젝트에 반영되는 파일은 반드시 전체 코드 기준으로 제공한다.**

### 1-3. 문서 요약/축약 금지
문서 작업 시 다음은 금지한다.
- 기존 md의 설명량을 임의로 줄이는 것
- 핵심 철학/배경/의도/예시를 삭제하는 것
- 최신화한다는 명목으로 “짧은 요약본”으로 바꾸는 것
- 현재 상태만 적고 기존 상세 서술을 버리는 것

문서 최신화는 반드시:
1. **기존 설명량과 서술 깊이를 유지**하고,
2. **현재 변경 사항을 추가**하는 방식으로 진행한다.

즉, 문서 작업의 기준은 **요약본**이 아니라 **완전판 갱신본**이다.

### 1-4. 공용 파일 임의 단순화 금지
특히 아래 파일은 공용 파일이므로 임의 단순화가 금지된다.
- `frontend/src/css/app.css`
- `frontend/src/css/topbar.css`
- `frontend/src/js/sidebar.js`
- `frontend/src/js/topbar-core.js`
- `frontend/src/js/config.js`
- `worker/src/index.js`

공용 파일을 수정할 때는 반드시:
- 실제 영향 범위를 먼저 분석하고
- 어떤 페이지/기능이 이 파일을 사용하는지 파악한 후
- 기존 동작을 유지하는 방향으로 수정해야 한다.

## 3. 프론트엔드 절대 원칙

### 3-1. CSS는 반드시 분리한다
현재 프론트의 CSS 구조는 아래와 같다.
- `app.css` — 전역 토큰, 공통 레이아웃, 사이드바, 버튼, 폼, 모달
- `topbar.css` — 상단 글로벌 메뉴 전용
- `board.css` — 커뮤니티 / 프로그램 문의 / 고객센터 공통
- `marketplace.css` — 제휴사 및 자유홍보 / 모집 및 의뢰 공통

이 원칙을 유지한다.

#### 금지
- HTML 내부에 대형 `<style>` 블럭 추가
- 공통 CSS를 한 파일에 다시 우겨넣기
- 페이지별 스타일을 인라인 style로 계속 누적하는 것

#### 허용
- 구조적으로 공통화 가능한 스타일은 공통 CSS로 이동
- 특수 페이지의 경우 별도 CSS 파일 추가
  - 예: `place-rank.css`

### 3-2. 폰트 원칙
Sherpain21의 공통 폰트 기준은 **커뮤니티 탭에 쓰는 폰트**와 동일하다.
즉, 기본 텍스트는:
```css
font-family: var(--font-korean);
```
를 기준으로 통일한다.

#### 적용 대상
- 탑바 메뉴
- 탑바 드롭다운
- 사이드바
- 게시판 탭
- 페이지 제목/설명
- 테이블/리스트 본문
- 모달

#### 예외
숫자/통계/눈덩이/순위 카운트는 다음 사용 가능:
```css
font-family: var(--font-mono);
```

### 3-3. 탑바 원칙
탑바는 다음 3파일을 기준으로 관리한다.
- `frontend/src/js/topbar-core.js`
- `frontend/src/js/topbar.js`
- `frontend/src/css/topbar.css`

탑바 변경 시:
- 메뉴 데이터는 `topbar-core.js`에서 관리
- 각 HTML은 `topbar.js`만 로드
- 탑바 라인과 사이드바 상단 경계선 톤을 맞춘다
- 메뉴는 텍스트 중심으로 유지하되 기능 버튼 아이콘은 허용

### 3-4. 사이드바 원칙
사이드바는 기존 복구본 구조를 보존한다.
- 기존 메뉴 트리 보존
- 기존 유저 영역 보존
- 하단 `가이드 / 고객센터 / 로그아웃` 구조 보존

사이드바를 손댈 때는 “간단히 줄인 버전”을 만들지 않는다.

### 3-5. 페이지 구조 통일 원칙
상단 메뉴 5개 페이지는 아래 구조 철학을 따른다.
```text
탭
제목/설명
액션 버튼
목록 제목 + 검색행
테이블
페이지네이션
모달
```

#### 게시판형 페이지
- 커뮤니티
- 프로그램 문의
- 고객센터
→ `board.css`

#### 마켓형 페이지
- 제휴사 및 자유홍보
- 모집 및 의뢰
→ `marketplace.css`

## 4. 백엔드 절대 원칙

### 4-1. `index.js`는 더 이상 계속 비대해지면 안 된다
현재 `worker/src/index.js`는 monolith다.  
앞으로 새 기능을 추가할 때는 **기능별 모듈 분리**를 우선 고려한다.

### 4-2. 단기 patch 허용, 장기 구조 통합 금지
긴급 테스트나 임시 패치를 위해:
- 함수 블럭을 하단에 붙이고
- fetch 내부 route를 404 직전에 추가하는 방식
은 **단기적으로 허용**한다.

하지만 이것을 장기 구조로 유지하면 안 된다.
최종적으로는:
- `shared/`
- `modules/`
- `routes/`
구조로 분리해야 한다.

### 4-3. request 마다 migration 금지
운영 요청 경로에서 아래가 반복 실행되면 안 된다.
- `autoMigrate()`
- schema ensure
- `ALTER TABLE`
- `CREATE INDEX IF NOT EXISTS`

스키마 변경은:
- deploy 전 수동 적용
- bootstrap 1회
- 별도 migration 파일
기준으로 처리한다.

### 4-4. UTF-8 safe JWT 유지
JWT payload에 한글이 들어갈 수 있으므로,
다음 방식은 금지한다.
```js
btoa(JSON.stringify(payload))
```

반드시 UTF-8 safe base64url 인코딩을 사용한다.

### 4-5. 공개 경로 호환 유지
다음 두 계층은 동시에 유지될 수 있다.
- 레거시 경로 (`/post/list`, `/attendance/check` 등)
- V2 경로 (`/api/community/*` 등)

외부 프론트와 이미 연결된 경로는 **호환 계층 없이 삭제 금지**다.

## 5. 문서 작업 절대 원칙

### 5-1. 문서 업데이트 방식
기존 md 문서를 업데이트할 때는 아래 원칙을 따른다.
1. 기존 문서의 설명, 배경, 예시, 철학을 유지한다.
2. 현재 변경된 파일/구조/배포/연결 관계를 추가한다.
3. 짧게 줄이지 않는다.
4. 최신화라는 명목으로 “요약본”을 만들지 않는다.

### 5-2. 완전판 갱신본 기준
문서 작업의 결과물은 항상 아래여야 한다.
- **설명량 유지**
- **설명 깊이 유지**
- **기존 섹션 유지**
- **현재 변경사항 반영**

즉 문서의 기준은:
- 요약본 ❌
- 축약본 ❌
- 완전판 최신화 ✅

### 5-3. 문서별 목적 유지
- `CURRENT_STATUS.md` → 현재 상태와 우선순위
- `FILE_MAP.md` → 연결 관계와 파일 역할
- `STYLE_GUIDE.md` → 실제 스타일 기준과 원칙
- `TOPBAR_FEATURES_SPEC.md` → 글로벌 메뉴 명세
- `BUSINESS_LOGIC.md` → 서비스 운영/과금/권한 정책
- `SECURITY_GUIDE.md` → 인증/권한/비밀 관리
- `DEPLOYMENT_GUIDE.md` → 실제 배포 절차

문서 목적을 섞지 않는다.

> 각 파일을 제공하기 전에 반드시 `SHERPAIN21_MASTER_PROMPT.md`를 먼저 읽고, 그 지침을 어기지 마라.  
> 기능 축소, 코드 생략, 문서 축약, 공용 파일 임의 간소화는 금지한다.

## 10. 최종 선언
이 문서를 읽지 않고 이루어진 수정은,
프로젝트 전체 기준에서 **유효하지 않은 수정**으로 본다.

모든 작업자는:
- 먼저 이 문서를 읽고,
- 지침을 준수하고,
- 기능 축소 없이,
- 문서 축약 없이,
- 전체 파일 기준으로 작업해야 한다.
