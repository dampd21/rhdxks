# Sherpain21 비즈니스 로직, 과금 체계 및 기술 아키텍처 통합 명세서 (Master) — 완전판 갱신본

마지막 업데이트: 2026-05-02  
원본 작성: Sherpain21 Product Team  
현재 반영: 워크스페이스 최신 구조 / 프론트 통일 / 커뮤니티 V2 / Worker 분리 준비 상태

본 문서는 Sherpain21(셰르파인 2.1+) 플랫폼의 핵심 수익 모델(BM), 눈덩이(토큰) 이코노미, 에스크로 중개 시스템, 커뮤니티/문의/고객센터/자유홍보/플레이스/블로그/스마트플레이스 등 기능이 어떤 기술적 아키텍처와 과금 규칙으로 동작해야 하는지를 **기획 + 데이터 흐름 + 과금 정책 기준으로 통합 규정한 마스터 문서**입니다.

모든 현금성 트랜잭션(눈덩이 증감)은 동시성 문제와 데이터 무결성을 위해 반드시 **Cloudflare D1의 원자적 처리(batch/transaction 성격)** 를 기준으로 다뤄야 하며, `snowball_transactions` 테이블에 상세 Audit Log가 남아야 합니다.

이 문서는 요약본이 아니라, 향후 기능 추가/리팩터링/백엔드 분리/프론트 구조 개편이 일어나더라도 Sherpain21의 서비스 정체성과 수익 구조를 일관되게 유지하기 위한 **완전판 기준 문서**입니다.

## 1. 플랫폼 비전 및 핵심 수익 구조 (6대 캐시카우)

Sherpain21은 기존의 "마케터와 자영업자를 분리하여 메뉴를 숨기는" 단순 SaaS 툴에서 벗어나, **모든 유저에게 기능을 최대한 오픈하되, 사용량(슬롯/눈덩이/요금제)으로 허들을 두는 Freemium & Upsell 플랫폼**으로 진화했습니다.

### 1.1 SaaS 구독 수익 (월/연간 결제)
- Basic(무료)
- Standard(월 39,000~59,000원)
- Pro(월 99,000~189,000원)
- 연 결제 시 10% 할인 적용 가능
- 결제 성공 시 요금제/권한/기본 슬롯/보고서 노출 범위 자동 연동

### 1.2 Enterprise / Franchise 맞춤 B2B 페이지
- 별도 구축 및 심화 상담 비용
- 지점 통합 현황
- 지점별 QC 관리
- 권한 분리형 보고 체계

### 1.3 에이전시 중개 수수료
- 플랫폼 내 제휴사(예: 올스, 고트마케팅 등) 거래 시 중개 마진 발생
- 공식 제휴 파트너사는 일반 홍보글과 분리된 구조로 우대 노출

### 1.4 B2B2C 리뷰어 모집 에스크로 수수료
- 업주(의뢰자)와 일반인/리뷰어(수행자) 간 미션 보상 지급 시
- **거래 대금의 10%를 플랫폼 수수료로 원천 징수**

### 1.5 낙전 수익 (Breakage Revenue)
- 수행자가 벌어들인 눈덩이는 최소 출금 기준 충족 시에만 출금 가능
- 예: 10,000원(또는 5,000원) 이상
- 기준 미달 상태에서 이탈하는 유저의 소액 자산은 플랫폼 순수익이 될 수 있음

### 1.6 실행사 배너 광고비
- 커뮤니티 및 제휴사 게시판 상단 스폰서 영역 판매
- 월 단위 배너 입점 구조
- 향후 관리자형 배너 슬롯 운영 가능

## 2. 재화 단위 (눈덩이)

### 2.1 기본 재화명
- 사용자 노출 명칭: **눈덩이**
- 기존 DB 컬럼명: `tokens`
- 코드/문서/프론트에서는 snowball 개념으로 매핑

### 2.2 가치 비율
- 1 눈덩이 = 1 KRW (원)

### 2.3 현재 환경
- 테스트/개발 환경에서는 가상 충전 / 테스트 세션 / dev session으로 지급 가능
- 운영 환경에서는 실제 결제/충전/출금과 연동 예정

### 2.4 눈덩이가 쓰이는 곳
- 자유홍보 추가 작성
- 미션 예치금
- 출석체크 보상
- 테스트/개발 지급
- 향후 슬롯 구매/보고서 확장/고급 기능 과금

## 3. 요금제별 기능 개방 및 슬롯/눈덩이 정책

모든 사용자는 회원가입 즉시 Basic(무료) 플랜으로 시작하며, 고급 기능 및 대량 처리, 상세 보고서, 슬롯 확장을 위해 Standard 또는 Pro로의 업그레이드를 유도합니다.

### 3.1 요금제별 권한 (SaaS)

| 기능 카테고리 | Basic (무료) | Standard | Pro |
|---|---|---|---|
| 플레이스 순위 조회 | 기본 1개 슬롯 | 기본 3개 슬롯 + 스냅샷 보고서 | 기본 10개 슬롯 + 심화 보고서 |
| 플레이스 SEO 분석 | 핵심 보고서 일부 | 전체 보고서 오픈 | 전체 오픈 + 맞춤형 확장 |
| 블로그 지수 분석 | 조회 쿨타임 1시간 | 무제한 | 무제한 |
| 키워드별 블로그 순위 | 단순 순위 조회 | 변동 알림 + 키워드 3개 | 댓글 자동화 + 키워드 5개 |
| 블로그 자동 포스팅 | 1일 1건 수동 | 일 5건 자동 | 일 20건 확장 |
| 리뷰 SNS 자동업로드 | 기능 설명 노출 | 일 5건 | 일 20건 |
| CPC 단가 추적 | 계정당 1회 | 일 10회 | 무제한 |
| 광고 시간대별 최적화 | 설명 오픈 | 설명 오픈 | 분석/고도화 |
| 유튜브 분석 | 설명 오픈 | 키워드 검색 (상위 5개) | 전체 오픈 + 심화 |
| 키워드 마인드맵 | TOP 3개 일부 공개 | 전체 오픈 | 전체 오픈 + 유입 분석 |

### 3.2 무료 전면 개방 기능 (트래픽 유도용)
플랫폼 체류 시간과 DAU 확보를 위해 플랜과 무관하게 최대한 공개하는 영역:
- 플레이스 리뷰 로직 분석 / 타업체 리뷰 분석
- 키워드 검색량/조합 / 급등 키워드
- 손익계산 및 매출 연동 기초 도구
- 리뷰 연동 + CS 보고서 / ROAS 기초 분석

### 3.3 눈덩이 완전 과금 기능
요금제와 무관하게 또는 무료 제공량 초과 시 눈덩이를 차감하는 기능:
1. 소상공인 데이터(010 번호 수집)
2. 부동산 데이터 수집
3. 사진 메타정보 변경 (EXIF)
4. 광고 소재 AI 생성기
5. 자유홍보 게시판 글쓰기 (최초 1회 무료 후 차감)
6. 슬롯 확장 또는 특수 보고서 확장 (향후)

## 4. 눈덩이 과금 상세 내역 (트랜잭션 로직)

| 기능 | 과금액 (눈덩이) | 설명 및 트랜잭션 로직 |
|------|----------------|------------------------|
| 회원가입 보너스 | +150 눈덩이 | 가입 즉시 지급 |
| 추천인 가입 보너스 | +1,000 눈덩이 | 유효한 추천 코드 입력 시 대체 지급 |
| 일일 출석체크 | +10~50 눈덩이 | 연속 출석일 기준 차등 지급 |
| 에스크로 의뢰 등록 | 의뢰금 + 10% 수수료 | 총 예치금 즉시 차감 |
| 에스크로 정산 | +의뢰금 | 승인 시 수행자에게 지급 |
| 자유홍보 등록 (1회차) | 0 | 최초 1회 무료 |
| 자유홍보 등록 (2회차~) | -500 | 자유홍보 추가 작성 비용 |
| 마케팅/순위 분석 | -300 예시 | 고비용 외부 리소스 기능 과금 예시 |
| EXIF 메타정보 변경 | -300 | 사진 메타 수정 비용 예시 |
| 테스트 눈덩이 충전 | +선택 금액 | 개발/테스트용 |
| 개발용 마스터 충전 | +1억 눈덩이 | 운영 전 제거 또는 보호 대상 |

### 4.1 현재 프론트 반영 상태
- 자유홍보 UI는 1일 1회 무료 + 이후 500 차감 정책 반영
- 출석체크 UI는 연속 출석 보상 개념 반영
- 미션 등록 UI는 10% 수수료 계산기 반영
- 실제 서버 연동은 커뮤니티부터 순차적으로 확장 중

## 5. 핵심 캐시카우: 에스크로 (모집/의뢰) 트랜잭션 상세 로직

### 5.1 기본 흐름
1. 의뢰자가 보상 눈덩이를 입력
2. 시스템이 수수료 10%를 계산
3. 총 예치금이 즉시 차감(Hold)
4. 수행자가 미션 신청/수행
5. 의뢰자가 승인
6. 보상은 수행자에게 지급, 수수료는 플랫폼 귀속

### 5.2 상태 흐름
```text
open → in_progress → completed
          ↘ cancelled / expired
```

### 5.3 현재 구현/설계 메모
- 프론트는 `missions.html + escrow.js`에서 검색/페이지네이션/등록 모달/예치 계산기까지 정리됨
- 백엔드는 `escrow_missions`, `escrow_applications`, `snowball_transactions` 구조 존재
- 승인/지급/잠금/상태 전환은 실제 API 정교화 필요

## 8. 백엔드 API 데이터 흐름 및 아키텍처 (Data Flow)

Sherpain21의 핵심 크롤링/분석 아키텍처는 Cloudflare Worker와 외부 서버(Render, Oracle)를 결합해 네이버/외부 API 제약을 우회합니다.

### 8.1 플레이스 순위 조회 (Place Rank)

```text
[프론트 place-rank.html]
  └─ SherpaAPI.rank.place({ keyword, placeId, kind, x, y, display })
      ↓
[Worker /rank/place]
  ├─ buildGraphQL(kind, keyword, start, display, x, y, deviceType)
  ├─ Oracle 프록시 호출
  ├─ normalizeItem(kind, item)
  └─ 응답: { keyword, placeId, kind, myRank, total, results[] }
      ↓
[프론트]
  ├─ 대상 업체 타겟팅
  ├─ 순위 카드 렌더링
  ├─ 전체 결과 렌더링
  └─ 추적 등록 시 snapshots 저장 + 크론 수집 가능
```

### 8.2 네이버 플레이스 GraphQL 프록시 아키텍처
현재 오라클 서버를 경유하는 방식으로 차단 이슈를 우회합니다.

```text
[Worker]
  └─ POST http://152.69.239.221:3000/naver/place
      ↓
[Oracle Server]
  ├─ API Key 검증
  ├─ 한국 IP 기반 네이버 호출
  └─ 결과 반환
      ↓
[Worker → 프론트]
  └─ JSON 파싱 및 정규화 후 응답
```

적용 엔드포인트 예시:
- `/rank/place`
- `/rank/proxy`
- `/place/themes`
- `/place/reviews`
- `/place/detail-gql`

### 8.3 플레이스 키워드 분석 / 북마클릿
- 사용자가 스마트플레이스 통계 페이지에 직접 로그인
- 북마클릿 클릭
- same-origin fetch 또는 보조 프록시 구조로 데이터 추출
- SHERPA IN 페이지에서 결과 시각화

### 8.4 부동산 데이터 수집
- 프론트 → Render → Worker → 네이버 부동산 API
- 또는 프록시 구조를 통한 우회형 수집

### 8.5 상위노출 URL 생성기 (Puppeteer)
- Oracle Puppeteer 서버 사용
- 네이버 검색 → 클릭 시뮬레이션
- 통계 유입값 생성

### 8.6 소상공인 데이터 (010 번호 자동 수집)
```text
[Worker /biz/collect]
  ├─ 네이버 검색/블로그 API에서 URL 획득
  ├─ 모바일 블로그 HTML fetch
  ├─ 정규식으로 010 번호 추출
  ├─ data-module JSON 파싱
  └─ 중복 제거 후 결과 반환
```

### 8.7 블로그 지수 분석 및 AI 포스팅
- 지수 분석: 외부 Flask/분석 서버 가능
- AI 포스팅: Groq / Gemini / 기타 생성 API 프록시
- Chrome 확장/자동 발행 도구와 연결 가능

| id | INTEGER PK | 자동 증가 |
| requester_id | TEXT | 의뢰자 user_id |
| title | TEXT | 미션 제목 |
| reward_per_person | INTEGER | 1인당 보상 눈덩이 |

| total_deposit | INTEGER | 예치금 (수수료 포함) |

| is_locked | INTEGER | 최대 인원 달성 시 잠금 |

### 10.3 posts / comments / attendance
커뮤니티 V2 기준 핵심 테이블:
- `posts`
- `comments`
- `attendance`

현재 프론트 커뮤니티 구조는 이 테이블들을 기준으로 실 API 연결 중이다.

## 11. 구현 원칙 (Atomic Transaction)

모든 눈덩이 관련 로직은 가능한 한 원자적으로 처리해야 합니다.

```javascript
await env.DB.batch([
  env.DB.prepare('INSERT INTO ...'),
  env.DB.prepare('INSERT INTO snowball_transactions (...) VALUES (...)').bind(...),
  env.DB.prepare('UPDATE users SET tokens = tokens - ?, updated_at = ? WHERE id = ?').bind(...)
]);
```

### 반드시 지킬 것
- 눈덩이 차감/적립과 실제 비즈니스 레코드 생성은 최대한 한 흐름으로 묶는다.
- 실패 시 중간 상태가 남지 않도록 한다.
- 거래내역 로그를 반드시 남긴다.

## 12. 보안 및 접근 제어

- 모든 인증 필요 API는 `Authorization: Bearer ...` 검증
- JWT payload에는 최소한 `sub`, `role`, `plan`, `name`, `iat`, `exp` 포함
- 공지사항 작성은 admin/operator만 허용
- 에스크로 승인도 본인 미션만 가능하게 제한
- 자유홍보/출석체크/미션 등록 등 눈덩이 관련 기능은 서버 기준으로 최종 검증
- 개발용 `/api/dev/session` 은 운영 전 제거 또는 보호 필요

## 14. 최종 선언
Sherpain21의 비즈니스 로직은 단순한 화면 구성이 아니라,
**눈덩이 경제 + 에스크로 신뢰 모델 + 커뮤니티 체류 시간 + 로컬 마케팅 데이터 도구**가 하나로 묶인 구조입니다.  
따라서 기능을 따로따로 구현하더라도,
항상 다음 4가지를 동시에 고려해야 합니다.

1. 수익 모델과 연결되는가?
2. 눈덩이 흐름과 충돌하지 않는가?
3. 운영자/일반 사용자 권한이 분리되는가?
4. 기술 구조(Worker/D1/프록시)와 실제로 연결 가능한가?

이 문서를 기준으로 모든 기능은 동일한 철학과 데이터 흐름을 유지해야 합니다.
